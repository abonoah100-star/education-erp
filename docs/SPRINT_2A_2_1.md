# Sprint 2A.2.1 — Prisma Binary Persistence Build Fix

تاريخ الإصدار: 24 يوليو 2026  
الإصدار: `2.2.1`

## سبب الإصدار
فشل بناء الـBackend أثناء تخزين صورة صاحب الكارت لأن مسار معالجة الصور ينتج `Buffer` من Node.js، بينما Prisma 6.19 يولد نوعًا دقيقًا لحقل `Bytes` يعتمد على `Uint8Array`.

المشكلة كانت عند حد التخزين فقط، وليست في الصورة أو Migration أو PostgreSQL.

## الإصلاح الجذري
- إضافة محول صريح عند حد Prisma باسم `toPrismaBytes`.
- نسخ بيانات الصورة إلى `Uint8Array<ArrayBuffer>` مملوك ومستقل قبل الحفظ.
- استمرار Sharp وطبقة الرندر في استخدام `Buffer` دون تغيير مسؤولياتها.
- استخدام نفس البيانات المحولة في حساب SHA-256 والحجم والحفظ.
- إضافة اختبار Regression يثبت سلامة النسخ ونوع الـArrayBuffer.

## ما لم يتغير
- لا يوجد تعديل جديد في قاعدة البيانات.
- لا توجد Migration جديدة في هذا الإصدار.
- لا يوجد Workaround أو تحويل نوع قسري بـ`as`.
- لا يتم حذف صور أو كروت أو إعدادات موجودة.

## معيار الاعتماد
1. نجاح `prisma generate`.
2. نجاح `nest build`.
3. تطبيق Migration الخاصة بـSprint 2A.2 إن لم تكن طُبقت سابقًا.
4. نجاح Seed.
5. تشغيل الـBackend والـFrontend والـGateway.
6. رفع صورة طالب وإصدار كارت بنجاح.
7. ظهور الخط العربي والتسلسل والصورة الافتراضية كما هو مطلوب.
